# 独立双搜索后台与 A/B 对照

实验入口：`scripts/compare_search.py`。生产 `build_searcher()` 不导入实验模块，未新增 HTTP 服务、端口或前端，也没有正式版替换入口。

审计记录：首轮实测版本 `20261117.1` 的内存查询/页面缓存独立，但遗漏了学校栏目自动发现的持久缓存路径，两组可能共享栏目元数据。该轮结果必须标为探索性对照，不能作为严格独立 A/B 胜负结论。后续保留版为每组设置独立 `ARCHIVE_CACHE`，新增隔离回归；修复版未擅自追加一轮真实付费测试，原始结果保留。

首轮同时暴露出原有共用核验代码的缺陷：`exchange` 专家缺少 `source_ids` 映射，调用工具契约会抛 `KeyError('exchange')`。在服务器以合成材料、零付费请求复现。保留版补齐公开网页/学校目录/学校记录映射，并验证所有已注册专家均能描述工具；这项修复只安装在独立测试源码，正式 ICT 服务仍保持原版本，不自动替换。原始付费试验未在修复后重新运行。

## 运行方式

在隔离目录使用服务器现有 Python 环境运行。凭据从已授权的 ICT worker 进程环境中只读取得，保存在进程内存；所有费用账本、查询轨迹、原文证据和报告写入单独的私有实验目录，拒绝将输出设为生产源码或生产数据库目录。不要将真实简历、查询轨迹或结果文件提交到 Git。

```sh
python scripts/compare_search.py prepare --input /private/path/resume-redacted.txt --output /private/path/prepared.json
python scripts/compare_search.py run --input /private/path/prepared.json --output /private/path/comparison --seconds 900
```

`prepare` 只执行一次画像和拆分。`run` 启动 `single`、`dual` 两个独立进程，共用同一份拆分快照、相同开始时刻和总时限。每组保留相同的 GLM 搜索引擎、核验并发、DeepSeek 证据抽取模型、取证规则及原始查询计划。没有跨组查询缓存、网页读取缓存或成功答案共享。共同预处理费用单独列出，不重复计入两组搜索费用。

长简历如果触发现有拆分提示词的每次最多 20 条限制，使用 `prepare --section-split --reuse-profile /private/path/initial-prepared.json`。它复用首次画像，按简历现有章节分别拆分后汇总，重新编号，A/B 共用相同完整快照。该实验性输入准备不修改正式版拆分提示词；初次预检查费用与补齐费用分别记录。

## 并行核验结构

保留测试后台默认使用 `--pipeline next`，两个搜索组均采用同样的调度、拆分和读取策略。历史调度可用 `--pipeline legacy` 重现。

- 参考 10 月 7 日提交 `7b9ecc0` 的陈述线程池和 10 月 12 日提交 `e120058` 的专家分工。学历、专利、论文、奖项等类别共享执行位，空闲后轮换启动其他可执行类别。研究生学历仍可等待前一学段形成推免定位线索，依赖作品的任职、教学和艺术核验仍等待已选作品。最终报告保持原顺序。
- 每条检索约 90 秒，初始读取分成最多四页的小批次，每批最多约 15 秒并给抽取预留时间。读取请求首次连接失败后切到其他入口，同源仍限速，单条程序异常记录错误类型并继续其余条目。上述时间针对实验运行，与搜索计费额度无关。
- 学校公示命中本人姓名但原站网络异常时，可按原标题补查同校的另一公开子站，经过原文、身份、学段、年份和奖名校验。摘要单列为线索，证书错误、访问禁止或验证码保留原原因。
- 新预处理优先按章节拆分长材料，保留无标题的前缀和后续章节，检查摘录确实来自该段正文并重新编号。已有共同快照可以直接复用。仅新拆分会修正明显的夏令营优秀学员分类。

当前结构验证使用合成样本和模拟服务。原对照报告仍对应原试验，真实站点可达性和综合取证收益须分别复测。

## 双搜索协议

1. 类别 Agent 使用已有学校、赛事和出版方目录。每个事项由 DS 规划一次，输入只有本事项的脱敏摘录、姓名、待核实要素、已知域名和原查询。建议必须保留原文锚点，年份不能来自猜测；模型自编域名不作为已验证入口。
2. GLM 执行最多两条白名单规划探针，同时保留正式版原查询。已有原查询涉及目录外的出版方时仍保留，不因实验白名单把正式版能够查到的来源屏蔽掉。
3. GLM 没有返回相关入口，或前一轮回读仍未取得可关联本人的证据时，把实际返回的标题/摘要、原文读取失败和证据过滤原因交给 DS 做一次查询改写，再调用一次 DS 原生搜索发现实际公开 URL。接口返回的 URL 才能成为新入口，不能直接执行模型猜出的 URL。现任机构排除仍生效。
4. 将实际发现的前两个不同域名交回 GLM 定向搜索。DS 实际返回的页面也可作为待回读线索，统一交给原生读取器、身份/年份/来源校验和最终规则判定；不把 DS 的解释当作事实，不自动加入正式白名单。
5. 同一事项的入口规划和原生搜索补查均缓存，后续原查询继续执行，但不会反复递归触发双搜索。最多两条规划探针、两个回传域名是一轮实验协议的固定分支宽度，不修改正式版额度设置。

## 时限和中间结果

每组从共同拆分之后开始计时，最多 900 秒。所有新增搜索、模型和公开网页请求检查相同截止时间。每 10 秒、每条事项判定后保存原子快照；正在检索的事项也保留已抽出的证据。监督进程到时终止实验子进程，后台实验不会无限继续计费。已经被供应商接受的远端请求无法由客户端撤回，费用报告区分收到回执的用量和未完成请求。

超时保留已取得证据，未执行及未完成事项明确标注超时；不能将超时误写成查无记录。模型结论必须通过现有 `judge`，队员顺序不能证明队长、拼音不能单独证明身份、推荐/录取不等于获得学位、项目资助说明不能证明结题、预印本不等于期刊发表。

## 输出及解释

每组包含私有 `result.json`、`status.json`、`trace.jsonl`，完成全流程时另有 `report.json`。报告应逐项比较已核实要素、部分支持、可回读来源、身份/年份/赛级差异、源站访问失败、执行时长、GLM 次数、DS 原生搜索与模型 token、估算费用和超时范围。实习人工背调事项不计入自动核验要素覆盖率。

本实验直接比较服务器分类核验引擎的检索和证据处理，不重新调用华为云 AgentArts 编排 API；两组都采用这一相同条件。因此结果不衡量 AgentArts 调度或云端会话的性能。

单份简历的一次 A/B 试验只能说明此样本和当前供应商/源站状态，不能证明所有简历的普遍胜负。更多链接不是更多有效证据；按统一取证标准比较，并保留每项出处供人工复核。实验版可独立保留，替换正式 ICT 版需要用户另行明确指示。
