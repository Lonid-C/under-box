# ICT 搜索补查流程

适用版本：`ict-full-20261117.4`。仅修改独立的 `full-workbench`，原项目与凭据保持隔离。

本轮排查发现，增加搜索次数不能解决查询方向错误：项目的唯一编号没有被使用，长英文题名被完整引号和中文姓名锁死，抽取器的解释文字进入学校查询，公告中的名单附件没有被后续读取，短暂连接失败又导致整个报告后续同站页面被跳过。一次搜索没有结果、正文读取失败、取得正文但身份不对应、公开材料只证明部分要素，应分别记录。

## Agent 中的执行顺序

1. `strategy.build_plan` 继续建立类别、学校、主办方、出版方和公开登记渠道；`retrieval_recovery.refine_queries` 增加有原文依据的补查路线，并在付费请求前去重。实习、GitHub 授权和零检索类别保持原有入口。
2. 项目先检索原文的项目/课题/基金编号。搜索引擎即便忽略引号并返回相近编号，也要剔除与原编号无关的结果；没有对应编号时，改用“编号 + 原项目主题”和“编号 + grant funding”两条补查路线。专利分别搜索带前缀和不带前缀的原申请号，从实际记录获取公开号，不将申请号拼成一个猜测的专利 URL。
3. 论文保留完整题名和 Crossref/OpenAlex 元数据查询，同时使用原题名中的短前缀或关键词发现版本。完整英文姓名可帮助找到出版方页面，但不能独立证明作者身份；不会只凭姓氏首字母确认本人。
4. 赛事增加“本人姓名 + 输入学校”的跨索引查询，发现直接被索引的官方 PDF。学校仍只是搜索线索；搜到其他年份/其他比赛的名单不能证明当前条目。
5. 校内奖项先查同校、同奖、原年份的整批公告。学校的项目、荣誉、奖学金、学生工作公告可以继续读取同校域内、相关主题的名单附件或公示，最多沿原有两层链接深度读取。使用实际链接，不猜地址，不绕过登录、验证码或 robots。
6. 每两次查询继续按相关性回读。已有的空结果改述、官方索引补查、来源隔离及失败替补仍生效。连接失败暂退避 30 秒，同源其他页面之后可以重试；HTTP 与 HTTPS、不同端口分别处理。SSL 校验失败不会通过关闭证书校验解决。
7. `collect` 记录路线、查询返回、正文失败原因和证据过滤结果。已有证据覆盖全部待核实要素及本人身份时停止后续查询；有限的原文锚点和计划遍历结束后也会结束，不生成无限补查循环。业务额度限制仍关闭。
8. 原 `extract_evidence`、`person_scope`、`paper_identity`、`source_guard`、`judge` 执行最终约束。DeepSeek 的诊断按钮继续解释已保存的记录，诊断意见不会直接改判，也不会自动执行模型生成的任意查询。

## 必须保留的证据边界

| 找到的材料 | 可继续核对 | 不能据此直接证明 |
| --- | --- | --- |
| 项目编号出现在论文资助说明 | 编号与项目的公开关联、论文作者记录 | 本人是项目负责人、资助金额、项目已结题 |
| 同一研究的相近英文题名 | DOI、预印本与期刊版本、出版时间 | 题名完全一致、预印本已在期刊发表、共同第一作者 |
| 赛事官方名单有姓名与学校 | 对应行、赛事年份、组别、奖级 | 队员排序代表队长、获奖比例、其他年份获奖 |
| 奖学金公告附带名单 | 附件中的本人、学段、奖名、年度 | 公告中所有人均获奖、评奖名额等于本人获奖次数 |
| 连接失败、403、验证码或无法解析文档 | 明确技术原因，寻找另一公开入口或请补材料 | 没有该人、经历不实、姓名不在未读取的名单里 |

## 运维与验证

旧 DOC 读取器由 `UNDERBOX_ICT_DOC_READER` 指向专用 antiword，保留原有文件大小、输出长度、超时和非宏执行约束。部署使用 Debian 官方源码及补丁集，在独立工具目录编译，不替换服务器原项目的运行环境。

回归使用合成材料和模拟服务，覆盖编号缺失/伪造、题名变体仅用于发现、完整英文作者的出版方回读、跨年/跨校附件过滤、现任机构排除、退避到期恢复、SSL 严格校验和 ICT 专用 DOC 读取器。真实报告不会作为测试夹具或写入仓库。手动网页研究和少量 GLM 验证不替代自动回归，也不将历史报告覆盖成新结论。
