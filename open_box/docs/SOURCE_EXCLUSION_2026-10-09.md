# 输入主页、GitHub 入口和活动分类修复

个人主页输入保存用户地址、规范化地址和实际跳转地址。检索结果先排除输入来源，回读后再次检查跳转地址，抽取和最终报告检查来源及转载原出处。搜索摘要、引擎预加载正文、自提供链接也遵守同一排除规则。协议、www、锚点、尾斜杠、URL 编码、查询参数排序和跟踪参数不改变页面身份；BNBU 教师目录入口和同一教师的中英文主页合并识别。保留页面身份查询参数，不排除整个学校域名或其他独立页面。PDF 输入仍能使用学校人物简介作为外部来源。

GitHub 补充入口由后端 `githubMaterialEligible` 控制：只有原始输入明确提及本项目的 GitHub 仓库/源码或关联仓库、PR、commit URL 才显示；仅项目分类、开源标签、熟悉 GitHub、全局个人账号和模型猜测的 repo 不能触发。缺少 URL 但明确提及仓库时仍能补充 URL。服务端同样拒绝给原文未提 GitHub 的项目补充材料。普通项目继续走普通公开来源，不主动查 GitHub。

增加教学活动、艺术成果类别及对应查询策略。LLM 提示明确区分活动与项目；规则纠正错分为项目的公开课、大师班、演奏、首演等。真实软件开发、科研、教改项目保留为项目。原文、已明示的角色和评价仍保留，评价/世界首演/最长等要素需单独证实。

验证覆盖：来源变体、跳转、引擎正文、摘要、自提供链接、转载原出处、同校独立页面；截图两条艺术教学陈述；真实工程和教改项目；原文 GitHub 关联与模型伪造实体；补充材料服务端校验；现有学历、荣誉、账号隔离和用量逻辑。浏览器示例使用合成数据，不写入线上历史记录，不调用真实候选人的付费核验。

修复影响新拆分和新核验；历史报告保留原记录，不自动重新判定。需要重新读取/上传后再核验。
