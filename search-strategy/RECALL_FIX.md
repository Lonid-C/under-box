# 搜索漏检修复记录

本轮目标：恢复已有检索路径的召回，保留有限预算和跨域并发回读。没有调整身份阈值或证据分级规则。

## 已复现的问题

- 搜索 API 返回余额不足，收集层捕获全部异常后将其当成空结果。
- 所有查询结束后才开始读页：后续慢查询可能耗尽时间，使前面已取得的链接全部失去读取机会。
- 动态学校域名发现额外发出一次未计预算的请求，且可能因为其他学校的一篇合作新闻，将后续查询锁到错误域名。
- 括号/英文名变体排在原始查询之间，固定查询预算下挤掉公众号等原有渠道。
- 长名单只截取前 12,000 字，末尾的姓名无法进入证据抽取。
- 同一页面不同统计参数重复占用读页名额。
- GitHub 已返回的结构化内容没有被使用；没有通用查询时，直接锚点也不会被处理。Crossref 查询类型没有分发到已有适配器。

新增固定样例在修复前运行 10 项：8 项失败、1 项错误、1 项通过。它们不访问外网，也不调用付费模型，专门检查能否保留已知命中。

## 改动

1. 每两条查询回读小批结果，保留后续读页名额；命中结果按相关性和查询来源轮转选择。
2. 原始渠道优先于新增拼写变体。空结果在同一搜索预算内尝试取消域限定或引号，所有请求都有计数。
3. 学校全称优先精确识别；动态域提示只复用现有结果、仅对本条陈述有效。站点提示不用于认定身份或提高来源等级。
4. 长页保留页首和姓名/成果附近的连续原文片段，不把模型概括当作原文。
5. 去重只移除 fragment 和 `utm_*` 参数；微信文章的 `__biz`、`mid`、`idx`、`sn` 等仍保留。
6. GitHub/Crossref 已有元数据直接送入抽取；Crossref 空结果可回退到通用查询。
7. 余额/鉴权/网络失败向上报告。每条查询的命中数、耗时、回读失败数和提取证据数进入现有进度日志。

## 验证方法与限制

在项目 `open_box/` 下运行：

```sh
make test PY=../.venv/bin/python
```

`tests/test_rules.py` 包含原有验收与工作区已有的错误传播测试；`tests/test_search_recall.py` 包含本轮新增漏检回归。

修复后上述命令结果：29 项现有验收和 13 项新增回归全部通过。环境未安装 Playwright，原有浏览器交互断言跳过；HTTP 演示服务检查通过。

本轮真实接口探测返回 `SearchUnavailable`，供应商提示“余额不足或无可用资源包”。因此，离线回归能验证上述程序行为，但不能代替真实候选人的搜索召回评测。资源恢复后，应使用用户确认的历史命中链接比对日志中的“搜索命中—页面回读—证据提取”三个阶段。

时间预算在任务调度点检查；已经发出的网络/模型调用仍受其客户端超时约束，并非可强制取消的墙钟截止。跨域下载保持并发，模型抽取沿用当前版本的串行顺序。
