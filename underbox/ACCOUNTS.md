# Underbox 账户与报告历史

线上网关由 `UNDERBOX_GATEWAY_DB` 指向 SQLite 数据库。当前线上版本共用一个工作进程，API 配置可在管理台修改并重新加载。网关校验会话，并把经过认证的用户 ID 转发给工作进程；报告和历史记录按用户 ID 隔离。

账户可在受保护数据库的 `user_search_keys` 表绑定专用智谱搜索密钥。工作进程按网关确认的用户 ID 读取绑定，在每次后台任务的上下文中使用；嵌套线程池继承该上下文，不修改进程全局环境变量。未绑定的账户继续使用原共享搜索配置，DeepSeek 沿用原配置。绑定账户的搜索仅使用专用智谱密钥，不借用共享 Brave 密钥，也不向全局自定义端点发送专用密钥。绑定损坏时明确报错，不能悄悄回退到他人的 API。

2026-10-10 按用户确认，`demo` 与 `demo2` 共用专用智谱搜索密钥。密钥保存在权限为 `600` 的数据库中，不通过会话、配额或账户列表接口返回；管理台现有 API 清单仍显示共享配置。绑定不会改变账户角色、核验额度或已完成报告。

每次成功核验后，工作进程把报告正文写入数据库的 `report_history` 表，按账户只保留最近 10 份。历史列表和报告读取都以服务端认证的用户 ID 为条件；退出登录后必须重新认证才能访问。退出此次查询会清除当前报告与前端过程日志，已完成的历史报告仍可回看。历史报告可查看和导出；问答及检索计划只针对当前核验开放，避免把旧报告与新报告的后台材料混用。

数据库位于服务器 `/opt/underbox/users/underbox.db`，权限为 `600`。部署前使用 SQLite backup API 备份该文件；数据库结构由 `store.init()` 在服务启动时迁移。代码发布前应分别检查 `index.html`、`serve.py`、`store.py` 的线上版本，避免覆盖其他人的新改动。
