# underbox

履历对账的界面。**单文件静态原型**，双击就能开。

| 入口 | 是什么 |
| --- | --- |
| `index.html` | **正式入口**：品牌落地页 → 拖入简历 → 动画切到主界面。内置 PDF 查看器 + 右下角问答 |
| `serve.py` | 本地服务：提供页面、把问答送到 DeepSeek Harness。**内嵌 PDF 预览和问答都靠它** |
| `sample-resume.pdf` | 三页演示样本，`?demo=1` 和初始状态用它渲染查看器 |
| `make_demo_pdf.py` | 生成上面那份样本（内容取自 `_data.json`，需要 reportlab） |
| `report.html` | 纯报告视图（早期那版）：直接看结果、不播动画、没有查看器与问答 |

```sh
./start.sh               # 一键启动（自动选 python、指向 open_box），然后打开 http://127.0.0.1:8787/
python3 serve.py         # 等价。直接双击 index.html 不可用——本页没有任何演示数据
```

两个调试入口（写死在 `index.html` 末尾，方便演示与截图）：

- `index.html?demo=1` —— 载入后自动播一遍完整流程（录屏用）
- `index.html#app` —— 直接进主界面，不播动画（截图用）

数据是 open_box 内置的虚构 fixture（候选人「林昱和」全部虚构，域名用 RFC 6761/2606 保留的
`.example`），页面顶部有 MOCK 标注。**不要把它当成真实核验结果。**

## 落地页与那一段动画

落地页只有三样东西：品牌、slogan（`TA 的优秀，滴水不漏`）、以及正中央的上传窗口。

**关键设计：上传窗口不是"另一张卡"，它就是主界面左栏那张卡本身。**
两边的 DOM 完全同一份，宽高、padding、内部文案一字不改，**只有位置不同**。
所以动画才能做成"这个窗口飞到它未来的位置"，而不是"淡出再淡入一个新页面"。

用 **FLIP** 实现（First–Last–Invert–Play）：

1. 量出卡片当前的位置（页面正中）
2. 切 `data-stage="hero"` → `"app"`（布局立刻跳到终态）
3. 再量一次，算出位移差，反向 `translate` 回去**并停住不动**
4. 下一帧把 transform 归零，880ms 缓出（`cubic-bezier(.22,.61,.36,1)`）收尾

**为什么是纯位移、不缩放**：位移不会让文字变形；一旦要缩，正中央的 400px 卡片
和左栏的 400px 卡片宽度不同，缩放会把字拉扁。为此把**左栏宽度和落地页卡片宽度
锁成同一个变量 `--colw: 400px`**——是设计迁就动画，因为这样动画才真的干净。

实测位移轨迹（连续采样卡片 x）：`440 → 295.1 → 150.4 → 77.4 → 45.4 → 30.4`，
增量 `-144.9 / -144.6 / -73.1 / -32.0 / -15.0`，是标准缓出，全程有中间帧。
点「换一份简历」倒放回落地页：`171.9 → 332.3 → 404.3 → 433.1 → 440`。

**同步发生的事**（都只动 `opacity` / `transform`，不影响布局，
否则会把正在飞的卡片拽偏）：

| 时机 | 什么 |
| --- | --- |
| 松手瞬间 | 虚线转实线 + 淡粉底 + 洋红脉冲；文案换成 `✓ 已接收 xxx.pdf`（**替换同一行**，不加行高，避免卡片尺寸突变） |
| 0ms | 卡片起飞；顶栏淡入（`-10px` 落下）、输入风险条后跟 80ms |
| 300ms | 右栏滑入，先显示「正在逐条核验…」占位 |
| 430 / 500ms | 概览、边界依次淡入上浮 |
| 900ms | 卡片落位后在卡内跑四步进度（每步 460ms） |
| 之后 | 11 条台账按 42ms 错位淡入 |

**校验**：非 PDF/DOCX/MD 的文件会抖动一下并提示"只收 PDF / DOCX / MD，这个是 .xxx"，
2.6 秒后自动恢复——不明说为什么不收，用户会以为坏了。

**可访问性**：`prefers-reduced-motion: reduce` 时跳过整段 FLIP，直接落位。

## 视觉语言

参考你给的 Maxcourse 那一版：**奶油底 + 2px 黑描边 + 硬阴影 + 洋红点缀**（neo-brutalist），
留白给得很大，所以虽然描边很重，整体还是通透的。

| 元素 | 值 |
| --- | --- |
| 底 | `#F6F3EC` + 26px 网格线（`rgba(20,19,15,.05)`） |
| 墨 | `#14130F`，描边一律 2px 实线 |
| 阴影 | `5px 5px 0` / `3px 3px 0`，**不用模糊**——硬阴影是这个风格的骨 |
| 点缀 | `#FF2E9A`（洋红）：品牌字、提示条、主按钮、引用竖线 |
| 圆角 | 4px，克制 |

洋红只做**品牌与动作**，**不做状态色**。状态一律走下面那套语义色，两者不混。

## 五态配色（照抄，别自行发挥）

| status | 标签 | 点 | 底 / 字 |
| --- | --- | --- | --- |
| `ok` | 已证实 | `#1D9E75` | `#E1F5EE` / `#085041` |
| `part` | 部分证实 | `#BA7517` | `#FAEEDA` / `#633806` |
| `ask` | 待澄清 | `#D85A30` | `#FAECE7` / `#712B13` |
| `none` | 未找到公开记录 | `#B4B2A9` | `#F0EDE6` / `#44413A` |
| `who` | 身份未确认 | `#B4B2A9` | `#F0EDE6` / `#44413A` |

**`none` 和 `who` 的点、底、字必须完全一样。** 两者都是"这条没结论"，画成不同深浅
会暗示一个是问题。区分靠标签文字，不靠颜色。

**不用红色。** `ask`（发现不一致）用橙而不是正红——差异可能只是后续接任、口径不同、
或材料未公开。这一点是产品立场在视觉上的落点，不是配色偏好。

## 布局决定与理由

**两栏：左边投料，右边逐条检验。**

| 区域 | 放什么 | 为什么 |
| --- | --- | --- |
| 顶栏 | 品牌 / 分区 / MOCK 标注 / 报告编号 | 虚构标注必须在视野内，不能藏 |
| 洋红提示条 | 输入风险，可展开看命中原文 | 它不是提示而是**可信边界**：说明送进模型的内容被改过，读下面任何结论前都该先知道 |
| 左栏 | 投料（拖放 PDF / 粘贴网页）· 概览 · 边界 | 入口与"全局"放一起，右栏专心讲每一条 |
| 右栏 | 筛选 + 11 条台账，点开就地展开详情 | 见下 |

**不要平铺成 11 张大卡片。** 那样要滚很久，而且看不到全局——而这个产品第一眼的价值
就是分布（几条证实了、几条没找到、几条要人看）。反过来只给统计也不行，"带出处"就没了。
所以是**一行一条的台账**，要细节就地展开。

**摘要里剥掉行首日期。** 简历原文逐字保留了 `2024.03　…`，而旁边已经有日期列，
不剥就是"2024.03 | 学生工作 | 2024.03 校学生会…"的重复。
**只在列表里剥**；详情里的「简历原文（逐字）」仍然一字不动。

**详情栏里「要素 · 逐项核对」放在证据之前。** 这是全篇最重要的一栏——
"证明了任职组织 ≠ 证明了职务"这句话靠证据列表讲不出来，是要素栏把
`职务=部长 未证` 单独拎出来才成立的。

**差异那一段必须带一句括注**（草稿里写的是「差异不等于造假：可能是后续接任、口径不同，
或材料未公开」）。不加这句，用户看到"公告显示周清让是部长"的第一反应会是"这人虚报"——
前面所有中性设计会在最后一步被直觉吃掉。

**「身份未确认」单独一段解释为什么不计入本人**，并原样写出矛盾字段
（如"学校不同：晴川师范学院"）。同名不是过错，只是不能算在本人头上。

**未找到时用虚线空框，不用红色也不用警告图标**，措辞落在"这不指向任何问题"。
11 条里有 3 条是这种，是最常见的结局。

## 交互

- **拖放 / 点选**：拖拽时高亮（虚线转实线 + 位移 + 去阴影），松手即开始核验，没有第二个按钮。
- **个人网页**：落地页的上传窗口下面有一行「或者，粘贴个人网页地址」，
  贴进 URL 后走同一条动画。视觉上刻意做得次要——主路径是 PDF。
- **筛选**：顶部 chip 或左栏图例都能过滤，两处状态同步。
- **台账行**：是真 `<button>`，带 `aria-expanded`，键盘可达。
- **换一份简历**：顶栏右侧，倒放动画回落地页并清空结果，方便反复演示。

## 内嵌 PDF 查看器

上传简历后，投料窗口里直接渲染 PDF，可翻页、可缩放，不用另开窗口。

**为什么用 PDF.js 自己画到 canvas，而不是 `<iframe>` 指向 PDF**：iframe 用的是浏览器内置
查看器——它其实更好用（自带搜索、打印），但**它的界面不属于我们**，而且跨域限制让你读不到
"当前第几页"，做不出自己的页码和翻页控件。既然要求是"窗口内内置一个查看器用于翻阅"，
那就得自己渲染。

| 控件 | 作用 |
| --- | --- |
| `‹` `N / M` `›` | 翻页；也可用 PageUp / PageDown |
| `−` `%` `＋` | 缩放（0.4×–3×），基准是当前的适应模式 |
| 适宽 / 适页 | 两种"100%"：铺满横向 / 整页塞进视口 |
| `⤢` | 放大阅读（下详）；`Esc` 退出 |
| `↗` | 在新标签打开原文件 |

### 三种尺寸

| 状态 | 卡片 | 阅读区高度（900px 视口实测） |
| --- | --- | --- |
| 落地页 | 520×自适应 | — |
| 停靠（默认） | 左栏 520 宽 | 查看器 648，舞台 573 |
| 放大阅读 | 860 居中，竖向撑满 | 查看器 730，**舞台 655** |

**放大阅读做成了居中的阅读窗口，不是铺满屏幕。** A4 是竖版——铺满 1400px 宽只会得到
"页面窄窄一条、两边大片死白"。限到 860px 并让它在竖向撑满，页面占比才合理。
进放大态默认切到**适页**（整页可见），退出回到适宽；工具栏两个按钮随时可以覆盖。

放大态会**隐藏四步清单**（那时它已经跑完，只会挤占文档空间）——就为这个，阅读区从 495 涨到 655。

### 真实上传不进服务器

拖进来的文件走 `URL.createObjectURL(file)`，只在本机内存里给查看器读，
**不上传任何地方**——底部的说明行会如实写明"本地文件，未上传到任何服务器"。
清掉文件时会 `revokeObjectURL`。

按钮上的"文件"是三页的 `sample-resume.pdf`（`make_demo_pdf.py` 生成，内容取自 `_data.json`），
真上传时显示的是你自己的文件名和页数——实测上传 open_box 那份 1 页的
`resume_lin.pdf`，查看器如实显示 1 页。

### 三个坑（都写进代码注释了）

1. **非嵌入的 CID 中文字体必须配 `cMapUrl`。** 简历这类 PDF 常用 `STSong-Light` 这种
   不嵌入字体的 CID 字体；PDF.js 没有 CMap 就只能画出线条、**画不出字**——画布看着是空白的，
   很容易误判成"渲染失败"。而且**含 cmaps 的 CDN 不多**：cdnjs 的 pdf.js 目录下没有 cmaps（403），
   要用 **jsdelivr**（或 unpkg）。脚本 / worker / cmaps 三样同源，少一个都出问题。
2. **每次渲染换一张新 canvas。** 同一个 canvas 上并发 `render()` 会直接抛错，
   而快速翻页时上一帧很可能还没画完。
3. **查看器要有固定高度。** 不设高度的话它会被内容撑开，缩放后把整页布局推乱。
   现在用 `min(72vh, 820px)`，页面高于它时在查看器内部滚动。

### 降级路径（不让它变成一个死掉的白框）

- **PDF.js 本身没拿到**（离线 / CDN 挂了）→ 退回 `<iframe>` 用浏览器内置查看器，能看多少算多少。
- **拿到了但打不开文档**（典型是 `file://` 下的跨域限制）→ 说明原因 + 给"在新标签打开"。

所以**内嵌预览需要 `serve.py`**；直接双击 `index.html` 时查看器会显示上面那条提示。

## 问答模块（右下角，真连 DeepSeek Harness）

页面右下角一个胶囊按钮「问问这份报告」，展开是对话面板。面板里**三个小块**是引导问题，
每个都从**本次核验的实际结论**里生成，不是泛泛的范例：

| 引导问题 | 依据 |
| --- | --- |
| 第 5 条判了「待澄清」，为什么不是「未找到」？ | c05 的"公告只证明了任职组织与起止时间，职务一项落空" |
| 这 3 条「未找到公开记录」的，帮我列一份补证清单 | 把 status=none 的三条按类别和日期列出来 |
| 第 9 条同名但学校专业都不符，我该怎么跟候选人确认？ | c09 的身份矛盾字段（学校不同、专业不同） |

换一份简历，这三条会跟着变——它们读的是报告数据，不是写死的文案。

### 面板可以自由拖动

拖标题栏就能把面板挪到任意位置。几个约定：

- **默认贴右下**（在胶囊按钮上方），拖过之后位置记进 `localStorage`，下次打开还在原地。
- **双击标题栏复位**回右下角，顺手清掉记住的位置。
- 拖动时把面板**夹在视口内**，窗口缩放时也会重新夹一次——不让它跑到屏幕外找不回来。
- 收起后胶囊按钮仍然固定在右下角。**入口位置永远不变，只有窗口可移动**——
  否则用户把面板拖到角落再收起，就找不到它了。

两个踩过的坑，都写进代码注释了：

1. **面板不能放在 `.chat-dock` 里面。** dock 上有入场动画的 `transform`，
   会把后代的 `position:fixed` **捕获成"相对 dock 定位"**（CSS 里非 `none` 的 transform
   会建立包含块）。现象是面板的 y 坐标差了正好 22px——就是 dock 的 `bottom:22px`。
   移到同级才是真的相对视口。
2. **不要给面板套 `.anim` 入场动画。** 它在入场那一刻还是 `display:none`（默认关着），
   而**给 `display:none` 的元素加动画不会启动**；`animation-fill-mode:both` 会把它
   永久按在起始帧 `opacity:0` 上——DOM 里存在、`getBoundingClientRect` 有值、
   就是看不见。面板自己展开时的 `chatIn` 就是它的入场，套两层反而坏了。

### 为什么需要一个本地服务

浏览器里的页面**没法直接跟 dsh 说话**：`headless` profile 是命令行，
`sdk` profile 是 stdio 上的 JSON-RPC，两者都不是浏览器能直接讲的协议。
所以 `serve.py` 起了个极小的本地服务（只用标准库），把问题连同**本页的核验结果**
一起喂给 `dsh --profile headless`，再把回答带回来。

```sh
python3 serve.py                    # http://127.0.0.1:8787
python3 serve.py --port 9000
python3 serve.py --dsh /绝对路径/dsh # PATH 上找不到 dsh 时
```

**必须从此服务打开页面**（`http://127.0.0.1:8787/`），聊天才连得上。
直接双击 `index.html`（`file://`）时，浏览器不允许它访问本地服务——
这时会**降级为离线演示回复**，并在状态栏写「未连接 · 离线演示」、
在气泡上打「演示」标签。不假装连上了。

一个实测细节：headless 的 **stdout 就是回答本身**，`dsh: reasoning:` 之类的诊断都走 stderr，
所以取 stdout 即可，不用解析前缀。

### 安全上的一点：注入原文不进 prompt

`render_material()` 报告输入风险时，**只说检测到了什么类型、在哪一行，不带命中原文**。

这件事分两层：

1. 不带 `excerpt`——那些行正是 open_box 从送入模型的内容里剔除的（注入指令、白底白字、
   极小字号、页面外渲染）。把它们传回去等于把刚筛掉的东西放回来。
2. 连风险描述的**匹配片段**也裁掉（`_risk_label()`），只留 open_box 自己的模式标签。
   因为 `detail` 形如 `命中提示词注入模式：忽略既有指令（匹配片段"忽略之前的指令"）`，
   而**注入内容可以是精心构造的**，让"匹配片段"恰好等于一条完整指令——
   引用它等于把指令原样递回去。

> 这条是有来由的：第一版我把 `excerpt` 和完整 `detail` 都传了进去，模型确实识别出
> "这段内容属于注入指令，我没有采纳"并主动说明了。**它这次判断对了，但这件事不该靠它临场发挥。**
> 检测层该做的剔除，不该在下游靠模型的警觉性补回来。

### 还没做的

- **不是流式**。回答一次返回（实测 5–22 秒），期间只有一个"正在思考"的三点动画。
  真流式要走 `sdk` profile 的 JSON-RPC 通道。
- **没有多轮上下文**。每问一次都是独立请求，模型看不到上一轮。
- **没有把报告之外的东西喂进去**（比如候选人自提供的材料），只喂了本页这 11 条判定结果。

## 数据与重建

数据内嵌在 `index.html` 里，夹在 `/*DATA_START*/ … /*DATA_END*/` 之间：

```js
const REPORT = /*DATA_START*/{ … }/*DATA_END*/;
```

`_data.json` 是从 open_box fixture 抽出来的中间产物。换了 fixture 后重新注入：

```python
import json, pathlib, re
data = json.loads(pathlib.Path('_data.json').read_text(encoding='utf-8'))
p = pathlib.Path('index.html'); html = p.read_text(encoding='utf-8')
p.write_text(re.sub(r'/\*DATA_START\*/.*?/\*DATA_END\*/',
    '/*DATA_START*/' + json.dumps(data, ensure_ascii=False, separators=(',', ':')) + '/*DATA_END*/',
    html, count=1, flags=re.S), encoding='utf-8')
```

字段对应 dsh 插件 `resume_judge_claim` 的 `presentationMeta`（见
`../dsh-resume-verify/README.md` §4）。要接真实数据，把 `REPORT` 换成从
`tool/result.meta` 或 `resume/verdict` 事件流里攒出来的同形对象即可。

## 还没做

- **报告本身还是静态的。** 拖入任何文件都展示同一份虚构 fixture 的判定结果，
  四步进度是演示性质的，不真的跑核验。**真连模型的只有右下角问答**；
  **真的是你那份文件的只有 PDF 查看器**（它读的是上传的字节）。
- **查看器只认 PDF。** DOCX / MD 只显示一句"这个格式没有内嵌预览"。
  真要做 DOCX 预览得换 mammoth 之类的转换，是另一件事。
- **查看器依赖 CDN。** PDF.js 从 jsdelivr 取（约 1.3MB）。离线时降级成浏览器内置查看器。
  想彻底离线就把 pdf.js + cmaps 拷进目录、改 `PDFJS_CDN` 为本地路径。
- **拖放不看文件内容**：只校验扩展名，不读字节、不看大小、不解析。
- **顶栏「来源分级」「报告导出」是占位**，只有「逐条检验」有内容。
- **窄屏没细调**：<980px 收成单栏并隐藏日期/类别/等级列，能用但没打磨；
  `--colw` 固定 520px，窄屏下卡片会拉满。**问答面板和阅读窗口在窄屏下也没调**。
- **问答每次都在等**：headless 一问一起进程，实测 5–22 秒，期间没有流式输出。
- **无障碍只做到及格**：拖放区可 Tab + Enter，台账行是真 `button` 带 `aria-expanded`，
  查看器的翻页支持 PageUp/PageDown；但没逐项跑过 WCAG。问答面板和阅读窗口都**没做焦点陷阱**。
- **落地页没有分享信息**：没有 meta description、没有 og 图。
